# Structural Reaction Lab — implementation coverage

This is a bounded net-reaction tool, not a universal reaction predictor. The UI layout and example collection were retained. See the [pre-refactor audit](reaction-engine-audit.md) for original restrictions.

## Before and after

| Reaction | Before | Now |
| --- | --- | --- |
| Hydrogenation | One C=C in an acyclic C/H molecule with 2–6 heavy atoms | Detects every isolated C=C in supported hydrocarbons; terminal/internal/branched, ordinary 5+ member rings, larger chains, separate sites; defined E/Z can be removed by hydrogenation |
| Halogenation | Same small alkene restriction; Br₂ only | Structural Br₂ and Cl₂ addition at each supported isolated C=C; no assigned product stereoisomer |
| Hydration | Ethene + water only | Acid-catalyzed net hydration at terminal and selected internal isolated alkenes; connectivity-derived Markovnikov orientation; symmetric ends equivalent; ambiguous orientation rejected |
| Hydrohalogenation | Absent | HCl/HBr/HI graph recognition and supported Markovnikov connectivity; no peroxide/radical pathway |
| Alcohol oxidation | 2-propanol only | Detects methyl/primary/secondary alcohol sites and creates aldehyde-stage/ketone connectivity; tertiary alcohols rejected; uses the selected alkali hypochlorite graph and full counterion mass |
| Aldehyde oxidation | Absent | Explicit Further oxidation + aqueous medium enables a selected aldehyde-to-acid reporting stage with hypochlorite; no automatic primary-alcohol-to-acid shortcut |
| Carbonyl reduction | Acetone only | Aldehydes and ketones, including larger chains and ordinary cyclic/aromatic-spectator cases, become their actual alcohols; acid/ester/amide carbonyls not matched |
| Esterification | Ethanoic acid + ethanol only | Actual carboxylic acid acyl carbon + actual primary/secondary alcohol oxygen form the ester; all supported acid/alcohol site combinations offered |
| Ester hydrolysis | Ethyl ethanoate + water only | Detects ordinary ester acyl–O linkages and returns their actual acid/alcohol fragments, including independently selectable repeated ester sites |
| SN2 | One Cl/Br, ≤5 heavy atoms, acyclic C/H/Cl/Br, methyl/primary | Cl/Br/I on sp³ carbon, larger alkyl chains, multiple leaving-group sites, methyl/primary and supported secondary/benzylic cases; tertiary and neopentyl-type severe hindrance rejected |
| SN1 | Same artificial size/element restrictions; tertiary only | Supported tertiary/benzylic centers in water, without a tiny-molecule whitelist; no general secondary or allylic carbocations |
| E2 | Rejects more than one distinct elimination product | Requires a leaving group and actual beta H; each distinct beta position gives a selectable constitutional product; symmetry-equivalent beta sites collapsed |
| E1 | Tertiary only; rejects multiple products | Supported tertiary/benzylic cases with beta H; separate constitutional products; water remains a non-consumed medium |

## Architecture and mapping

- `server/molecular_graph.py`: reusable alcohol, acid, ester, alkene, alkyne, aldehyde, ketone, amine and alkyl-halide detectors; H counts, substitution degree, beta H, allylic/benzylic context and symmetry/orientation helpers.
- `server/reaction_engine.py`: graph eligibility/reagent roles -> candidate sites -> selected-site transformation -> product validation -> complete mapped product fragments. Transformations apply to explicit H and preserve every reactant map ID, including atoms going to water/halide coproducts.
- `chemistry_server.py`: input identity resolution, condition assessment, engine integration and theoretical-amount metadata. Catalog membership no longer provides a reaction shortcut.
- `reaction_diagrams.py`: consumes the exact mapped products generated by the engine. The old second first-match transformation implementation was removed. Diagrams return atom provenance, broken/formed bonds and bond-order changes; 3D uses that same mapped product.
- Existing pathway buttons select mechanism **and site**, with no automatic first-site selection. Amber rings mark the chosen site in 2D; amber 3D halos mark its atoms retained in the main product. Existing purple hover/pin inspection and measurements remain separate.

Reaction atom maps are deterministic for the resolved canonical reactant graphs and survive the reaction/2D/3D pipeline. Supplied original atom maps are retained separately as `originalAtomMap` in source provenance, since separate reactants can reuse the same original map number. They are not claimed to be persistent Ketcher editor object IDs. No atoms are invented: introduced product atoms come from the selected reagent's mapped graph.

## Removed eligibility dependencies

Removed `_alkyl_halide_site`'s five-heavy-atom cap, Cl/Br-only restriction, single-halide requirement and blanket acyclic restriction; removed `_simple_alkene_bond`'s six-heavy-atom cap and single-C=C requirement; removed exact-pair product recipes as the recognition source for hydration, esterification, ester hydrolysis, alcohol oxidation and carbonyl hydrogenation. Product generation no longer looks up a memorized product SMILES.

Exact identities remain **only** for input aliases, display names, example catalog pairs, stable legacy example IDs and formula labels. Structural reagent constraints (such as a genuine diatomic H₂ or X₂ graph) and the existing computational size cap are intentional, not memorized organic compounds. A test clears every hard-coded reaction example and confirms the structural pathways still work.

## Validation and remaining boundaries

- RDKit sanitization checks valence/bond order; additional checks reject changed/missing/duplicate atom maps, changed elements/isotopes, net charge mismatch, unexpected radicals/implicit H, duplicate bonds or invalid main-product fragments. Invalid generated products are omitted with an explanation.
- Main 3D products retain the existing maximum of 80 explicit atoms. This is a resource/display limit, not a special molecule count.
- These are one-site, one-equivalent net transformations. Separate sites/options do not predict preferential reaction, conversion, rate, actual yield or product ratios. Multiple-site stoichiometry means one selected site, not exhaustive conversion of every group.
- Alkene additions currently require hydrocarbon substrates and isolated C=C; conjugated/styrenyl, heteroatom-substituted, alkyne, strained-ring and complex competing-functional-group cases are excluded. Equal substitution with inequivalent ends is not assigned a guessed regioisomer. Selected simple rearrangement-prone additions are rejected.
- Defined atom stereocenters are rejected. Defined alkene E/Z is only accepted for hydrogenation that removes it. New stereocenters/E–Z outcomes, chiral inversion and anti-addition are unassigned; a 3D conformer is not a stereochemical prediction.
- SN1/E1 retain tertiary/benzylic scope. Ring-bound leaving groups and allylic regioselectivity are rejected. E2 does not check anti-periplanar conformations. Rearrangements are not generated.
- Alcohol oxidation with hypochlorite shows a balanced **net oxidation stage**. For primary alcohols, displaying an aldehyde does not claim that an aldehyde can be isolated or that further oxidation stops. Further oxidation is a separate aldehyde input, explicitly selected stage and aqueous medium. The acid is its neutral reporting form, not a pH/protonation or isolation prediction.
- Oxygen-family rules use C/H/O substrates with supported group connectivity. Phenols, carbonates, acid/ester/amide reduction, tertiary-alcohol esterification and lactone hydrolysis are not passed off as ordinary supported cases. No new base-hydrolysis pathway was claimed.
- Charged organic substrates, radicals, isotopes and organometallics remain outside scope. Recognized hydroxide/hypochlorite salts have explicit spectator handling. No numerical concentration/pH or reaction kinetics simulation was added.
- **Acid–amine condensation is still not supported.** This needs separate salt-formation and validated amidation/dehydration rules. It is the recommended next family, addressing the methylamine test without falsely calling every acid–amine mixture an amide reaction.
